Case 07 · Automação de testes de API

Da POC à Implantação de Testes Automatizados de API com Playwright

Comparação entre RestSharp e Playwright em C#, escolha da solução e evolução para uma automação de APIs REST e GraphQL em funcionamento.

Playwright C# REST GraphQL Allure Report Azure DevOps

Visão geral

  • Origem Prova de conceito entre RestSharp e Playwright
  • Linguagem C#, alinhada à stack de desenvolvimento
  • Estado atual Testes REST e GraphQL em funcionamento
  • Em evolução Integração à pipeline corporativa

Contexto

A escolha da ferramenta precisava considerar tecnologia, manutenção e sustentabilidade da solução.

A área de Qualidade ainda não utilizava automação de testes de API de forma estruturada. A POC foi criada para comparar alternativas compatíveis com C# e apoiar uma decisão técnica alinhada à realidade da equipe.

Aderência à stack

C# já era utilizado no desenvolvimento das aplicações, o que reduzia a distância entre o código do produto e o código dos testes.

Manutenção compartilhada

A escolha da linguagem permitia que Desenvolvimento também apoiasse a manutenção dos scripts quando necessário.

Escalabilidade

A solução precisava atender APIs REST e GraphQL e permitir expansão para outros tipos de automação.

Feedback e rastreabilidade

Relatórios, execução paralela e integração futura à pipeline foram considerados essenciais para a evolução da iniciativa.

Estrutura da iniciativa

A trajetória foi organizada em quatro estágios.

O case diferencia claramente o que foi validado na POC, o que foi escolhido, o que já está implantado e o que permanece em evolução.

1. POC validada

RestSharp e Playwright foram comparados em C#, com testes REST, GraphQL, autenticação, asserts e configuração por ambiente.

2. Playwright selecionado

A decisão considerou relatórios, paralelismo, possibilidade de expansão e integração com ferramentas do ecossistema.

3. Automação implantada

Os testes de API em C# passaram a funcionar cobrindo cenários REST e GraphQL.

4. Pipeline em implantação

A integração das execuções automatizadas à pipeline corporativa permanece em andamento.

Decisão de linguagem: C# foi mantido por já ser a linguagem de desenvolvimento das aplicações, facilitando colaboração, manutenção compartilhada e menor dependência exclusiva de QA.
